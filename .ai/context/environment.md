# Environment context

Where this project runs, what it expects of a development machine, and what an agent may do in each place. This file states project policy. Whether a tool is
installed on a particular machine is a local fact, and belongs in [`environment.local.md`](#this-machine).

**Never put a secret here.** This file is committed and read by agents. Name the profile, the role or the vault path — never a key, a token or a credential.

## Deployed environments

| Environment | What it is                                                        | How it is reached                      | What an agent may do                                            |
| ----------- | ----------------------------------------------------------------- | -------------------------------------- | --------------------------------------------------------------- |
| Local       | A developer machine: macOS, Windows or Linux                      | The repository checkout, `npm run dev` | Build, test, run the app                                        |
| CI          | GitHub Actions `ci.yml`: typecheck, link check, build on macOS    | A push or PR to `main` or `release/**` | Read the results. Never weaken a check to make it pass          |
| Release     | GitHub Actions `release.yml`: signed installers for three systems | A pushed `v*` tag                      | Nothing. Never push a `v*` tag; the developer releases          |
| Website     | GitHub Pages from `docs/` on upstream `main` (`munderdiffl.in`)   | A merge to upstream `main`             | Edit `docs/` and `blog/`. What lands on upstream `main` is live |

## Constraints

- Node.js 18 or later, with npm. CI uses Node 20. The project uses npm only: do not use `yarn` or `pnpm`.
- `node-pty` is a native addon. A C/C++ toolchain must be installed, and `postinstall` rebuilds the addon against the Electron ABI.
- To run an agent in the app, at least one agent CLI must be on `PATH`. `claude` is the default command.
- `blog/` and `landing-remotion/` are separate npm packages with their own lockfiles. The root `npm install` does not install them.
- No Docker and no database server. The app keeps its state in SQLite (`better-sqlite3`) and in the hive folder on disk.
- Signing and notarization need secrets in `.env.signing` and Apple keys. They are not in the repository, so a local `npm run dist:mac` makes an unsigned build
  at best.

## This machine

If `environment.local.md` exists beside this file, read it before running a command or assuming a tool is available. It describes the machine and session an
agent is actually running in — often generated by a sandbox — and where it disagrees with this file, it is right about the here and now. It is never committed,
never indexed, and never edited by an agent.

To provide it, copy or generate a sandbox's own description to that path, or write a few lines by hand. A symlink works only when its target is readable from
inside the sandbox; a link out of the project usually is not.

When the same setup is used on more than one machine, describe it once as a committed profile in [`../environments/`](../environments/_index.md) and make the
local file a single line naming it: `This machine: environments/macos-sandbox.md`. Git then carries a fix to the profile to every machine that uses it, and only
the one line stays local. A profile holds no credentials, no token contents and no personal paths; those stay in the local file.
